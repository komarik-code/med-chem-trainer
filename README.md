# ХімТренажер

Мобільний вебтренажер для тестів з медичної хімії. Повністю статичний: без бекенду і без авторизації. Прогрес зберігається в браузері (localStorage).

**База:** 885 питань у 3 темах, взятих із файлів `sources/*.rtf`:

| Тема (з файлу) | Питань |
|---|---|
| Медична хімія (самостійна робота) | 54 |
| Медична хімія (тести) | 422 * |
| Медична хімія (ситуаційні задачі) | 409 |

\* У джерелі 423 записи. №423 — обрізана копія №230: у ній немає варіантів відповіді й не позначено правильну. Тому вона не імпортується; повне питання №230 є в базі. Деталі в `scripts/conversion-report.txt`.

## Можливості

- **Режими:** Навчання (відповідь видно одразу, можна повертатися назад), Іспит (перевірка в кінці, вибір кількості 10/20/30/50/усі), Усі питання, Випадковий тест, Повторення помилок, Слабкі місця.
- **Помилки:** неправильні відповіді автоматично потрапляють до списку повторення. Питання виходить зі списку після 2 правильних відповідей поспіль. Історія спроб не видаляється.
- **Слабкі місця:** пріоритет залежить від частки помилок, їхньої кількості та давності останньої помилки.
- **Типи питань:** одна правильна відповідь вибирається одним дотиком. Кілька правильних відповідей вибираються з кнопкою «Підтвердити»; зараховується лише точний набір без зайвих.
- **Прогрес:** статистика за темами, історія тестів, експорт та імпорт JSON для перенесення на інший пристрій, скидання з підтвердженням.
- **Інтерфейс:** світла, темна або системна тема. Незавершений тест переживає перезавантаження сторінки. Хімічні індекси (H₂SO₄, 1s²2s²…) і картинки-схеми з бази збережено.
- **Клавіатура на ПК:** `A–E` або `1–5` — вибір, `Enter` — підтвердити / далі, `←` `→` — навігація.

## Локальний запуск

Потрібен Node.js 20+.

```bash
npm install
npm run dev        # http://localhost:5173
npm run build      # збірка в dist/
npm run preview    # перегляд збірки
```

## Оновлення або додавання тем

Кожен файл `sources/<id>.rtf` — окрема тема. Назва теми береться з заголовка файлу.

```bash
# потрібні python3 і LibreOffice (команда soffice)
cp "новий файл.rtf" sources/7001.rtf
npm run convert    # RTF → public/data/*.json + картинки + звіт
npm run verify     # незалежна звірка JSON з оригіналами
```

Конвертер очікує формат експорту з системи тестування: `N.<tab>питання`, далі варіанти `A.`…`E.`, правильний позначено `*`. ID питання — хеш його тексту й варіантів. Він не змінюється між запусками, тому історія відповідей не губиться при перенумерації.

## Публікація на GitHub Pages

1. Створіть репозиторій на GitHub (наприклад, `med-chem-trainer`) і запуште код у гілку `main`:
   ```bash
   git init && git add . && git commit -m "ХімТренажер"
   git branch -M main
   git remote add origin https://github.com/<user>/med-chem-trainer.git
   git push -u origin main
   ```
2. У репозиторії: **Settings → Pages → Build and deployment → Source: GitHub Actions**.
3. Workflow `.github/workflows/deploy.yml` сам збирає й публікує сайт після кожного push у `main`. Адреса: `https://<user>.github.io/<repo>/`.

`base` для Vite визначається автоматично з назви репозиторію. Для ручної збірки під інший шлях: `BASE_PATH=/my-path/ npm run build`. Маршрутизація hash-based (`#/quiz`), тож оновлення сторінки на GitHub Pages не дає 404.

## Структура

```
sources/            оригінальні RTF-бази
scripts/convert.py  конвертер RTF → JSON
scripts/verify.py   звірка JSON з оригіналами
public/data/        index.json, <id>.json, img/
src/lib/            типи, завантаження даних, сховище, логіка сесій і статистики
src/components/     UI-компоненти (питання, варіанти, картки, діалоги)
src/pages/          Головна, Тема, Налаштування тесту, Тест, Результати, Помилки, Прогрес
```
